# Claude Code settings

This file records why the managed Claude Code configuration is the way it is, where the configuration and the [settings](https://code.claude.com/docs/en/settings), [environment variable](https://code.claude.com/docs/en/env-vars), and [sandbox](https://code.claude.com/docs/en/sandboxing) references do not show it: motives, user decisions, runtime traps, and when each choice stops applying. Re-check runtime-dependent claims after a Claude Code upgrade.

## Ownership

`~/.claude/settings.json` and `~/.claude.json` stay partially managed per the [configuration ownership boundary](../../.github/CONCEPTS.md#configuration-ownership), so that keys Claude Code writes at runtime survive applies. Do not turn their modifiers into complete templates; `chezmoi re-add` cannot reconcile these targets.

A top-level key in `settings.json` is managed (declared in `.chezmoitemplates/claude/settings.json`, overwritten on every apply), a seed (declared in `$seeds` in `dot_claude/modify_private_settings.json`, written only when missing), or undeclared (left as Claude Code wrote it). Removing a key from the fragment makes it undeclared without deleting its live value, so retiring a key also means deleting it from the live file.

Only `model` is a seed, because `/model` changes it routinely and restoring it on every apply would undo that use. It seeds the `opus` alias rather than a model ID, because a seed is written once and an ID would freeze each machine on the generation current at its first apply. Being editable inside Claude Code does not make a key a seed: `permissions` changes through `/permissions` and stays managed, so make such changes durable in the fragment.

Declare no effort setting. `/effort` saves per-model levels under `modelSettings`, which a managed subtree would erase on every apply; Opus 5.5 ignores a top-level `effortLevel`, so it cannot serve as a seed, and a new machine starts at `medium` until `/effort` saves a level. `CLAUDE_CODE_EFFORT_LEVEL` overrides every session and makes `/effort` report that its change was not applied.

[`managed-settings.json`](../../.chezmoitemplates/claude/managed-settings.json) holds only keys that every session must honor, including runs started with `--setting-sources project,local`, which skip user settings: any interactive session without `disableDeepLinkRegistration` re-creates the `claude-cli://` URL handler app, and one without the privacy variables reports telemetry. Keep a key out of it when a harness or `--settings` must be able to change it, because no lower level overrides a managed key and only sudo edits the file; keep its keys out of the user fragment. Any managed settings file makes Claude Code seat its bundled `cc-plugin-sec-default@builtin` outermost unless managed `prependPlugins` is set, and that plugin routes every classic hook event past user-installed plugins, so preallow, which learns the permission mode only from those events, judges nothing in a session that starts with it seated; the empty `prependPlugins` list leaves it unseated, because this file holds no organization policy for it to protect. [Its setup script](../../.chezmoiscripts/run_onchange_after_setup-claude-managed-settings.sh.tmpl) installs it as root-owned `/Library/Application Support/ClaudeCode/managed-settings.json` and needs sudo, so apply it from an interactive terminal. Managed sources are first-wins: if a subscription account ever receives server-managed settings, they replace this file except for cross-source keys such as `env`, so confirm that `/status` lists `Enterprise managed settings (file)` in both launcher modes.

`modify_private_dot_claude.json` replaces each source-declared MCP server whole, so a transport field removed in source also disappears from the live entry.

## Session behavior

- `CLAUDE_CODE_RETRY_WATCHDOG=1` keeps unattended sessions waiting through retryable capacity errors. Keep `fallbackModel` unset while it is on: a fallback would silently downgrade the runs the watchdog exists to keep on the requested model.
- `tui` stays `fullscreen` because clients with different terminal widths attach to the same sessions, and classic rendering leaves hard-wrapped copies in scrollback after a resize. Leave `CLAUDE_CODE_DISABLE_MOUSE` unset: fullscreen does its own scrolling, and that override blocks wheel and touch scrolling.
- `CLAUDE_CODE_FORK_SUBAGENT=1` makes `claude -p` and the Agent SDK background subagents with the fork prompt, as interactive sessions already do, so headless replays and probes exercise the same subagent behavior as the terminal.

## Privacy and feature flags

`DISABLE_TELEMETRY=1` also disables the client that evaluates server-side feature flags, and no setting keeps flags while dropping events, so every flag-gated feature stays at its default. Before adding a setting, check whether the client reads it only behind a flag: `precomputeCompactionEnabled` (`tengu_sepia_moth`) and `autoDreamEnabled` (`tengu_onyx_plover`) are such settings and change nothing here. Leave `CLAUDE_CODE_GB_DISK_CACHE_WHEN_TELEMETRY_OFF` unset: it only reads a flag cache that sessions with telemetry off never write. Do not fold the privacy variables into `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, which also disables automatic updates.

`skipWebFetchPreflight=true` is a user decision. The preflight sends each WebFetch hostname to Anthropic's blocklist lookup, and [lookup failures can block fetches on otherwise working networks](https://github.com/anthropics/claude-code/issues/6388). WebFetch permission rules still apply.
## Permission rules

Rules resolve before the auto-mode classifier sees an action: a deny match blocks, and an allow match skips review except for documented cases such as protected paths and commands that carry per-command allowed domains. `sandbox.excludedCommands` decides only where a command runs, so an excluded command without an allow rule still goes to the classifier; do not mirror one list into the other.

- Classify a new credential path in the shared [agent guard](../../.github/CONCEPTS.md#agent-guard) first; it covers the agent's own Bash and file-tool calls in every runtime. Add a `Read` or `Edit` deny here only for what the guard cannot reach, knowing that Claude merges those rules into the sandbox's `denyRead` and `denyWrite` for every sandboxed process: npm reads `~/.npmrc`, so that file has only an `Edit` deny. Put a credential directory in `sandbox.filesystem.denyRead`, not a `Read(<dir>/**)` deny: after a `cd` into a target Claude cannot resolve, such as a glob, it denies any relative read that a `Read` deny could match, and a directory pattern matches every file name. Add no `Bash(*name*)` deny: it matches the whole command text, so it blocks commands that merely mention the name, while a glob such as `~/.np*rc` slips past it. Do not add `~/.ssh` deny rules back: the guard allows public keys, client config, `allowed_signers`, and `known_hosts` inside that directory, which a deny glob cannot express.
- Keep bare `Bash`, `PowerShell`, `Agent`, `Monitor`, and wildcarded interpreters, shells, or package-manager `run` commands out of `permissions.allow`: `auto` mode strips them before matching.
- `Bash(oracle:*)` is allowed because Oracle sessions continue after the invoking Skill's turn, when frontmatter preapproval no longer applies; `oracle` itself runs sandboxed. `Bash(snow:*)` serves the direct-command and native-SSO path owned by [Snowflake CLI execution](../../.github/CONCEPTS.md#snowflake-cli-execution), which also needs its sandbox exclusion.
- `Bash(codex:*)` and `Bash(pi:*)` are allowed by user decision: agents pick per-run flags, such as an approval-disabling `-c 'approval_policy="never"'`, that the classifier denies as `Create Unsafe Agents` from the command text alone, and an instruction against each flag would not cover the next one.
- Other host CLIs get no global allow rule. Git and similar commands keep their narrower Skill grants unless a current-version reproducer shows Claude denying the matching grant; `chezmoi` and `docker` stay on the classifier path although they are sandbox-excluded.

## Auto mode

The classifier reads `autoMode` only from user, managed, and `--settings` flag settings, never from a project `.claude/settings.json`, so this fragment holds all of its persistent configuration. Under the server-side review these sessions use, sandboxed and read-only commands also wait for the classifier.

- `autoMode.environment` carries machine-wide trust facts only: the Maskey credential store and its legitimate use, so a credential mention is not read as exploration, and the non-public scope, so delivering task material inside it is not read as egress. The classifier otherwise trusts only the working repository and its remotes, so the scope entry restates the scope predicate instead of naming accounts or services. Keep `$defaults` first, so the built-in entries stay, and use the `**Slot**: value` form; a custom slot sits beside the built-in one of the same name.
- `autoMode` declares no `allow` entries; `preallow@entwining-mods` handles steps of the user's task the classifier would deny, because it reads the user's words and allow entries cannot. In replays, allow entries for local Git work and for requested merges each cleared only part of their denial class, and entries restating the authorization standard moved denials both ways without raising the allow rate. Add one only for a denial preallow leaves to the classifier, with a replay that loads the global instructions and shows the classifier denying without the entry and allowing with it.
- The setup onboarding has two switches. `skillOverrides` `auto-mode-setup: off` disables the `/auto-mode-setup` command and its prompt, but only in sessions that load user settings; `autoModeEnvSetup.dismissed` in [`claude.json`](../../.chezmoitemplates/claude/claude.json) suppresses the prompt in every session, including evaluation runs started with `--setting-sources project,local`.

## Sandbox

- `excludedCommands` entries are command shapes, not wrapper-aware policies. The invocation is exempt only when every segment (split on `&&`, `||`, `|`, `;`, `&`, newline) is an excluded command with only its own arguments, apart from a file-descriptor duplication such as `2>&1`. A command substitution or heredoc, any non-exempt segment, or an inline assignment keeps it sandboxed, except a bare `env` or `time` prefix and assignments the CLI treats as inert (`TERM`, `LANG`, `NODE_ENV`). Git's `-C`, `-c`, `--git-dir`, and `--work-tree` fail a built-in check that no entry can override; `git --no-pager` stays exempt. Broaden a matcher only after an observed failure.
- A sandboxed socket client whose socket is missing from `allowUnixSockets` fails with a bare `Operation not permitted`, and `2>/dev/null` hides even that while the call still fails.
- `ps` and `pgrep` are excluded because Claude's Seatbelt profile lets a sandboxed process see only processes in the same sandbox, and no setting widens that. A `ps … | grep` pipeline therefore stays sandboxed and fails, while `pgrep -lf PATTERN` works alone. Remove both entries once a sandboxed `ps -ax` lists outside processes.
- Keep `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR=1`: the Claude global instructions tell agents that a `cd` does not carry over between Bash calls, so a plain excluded `git` always acts on the session's working directory.

### Write paths

`allowWrite` lists places sandboxed work writes whatever project the session started in. A repository outside the working directory is task-specific and does not belong here. Add a path only after an observed denial, never a whole home or source tree.

- `~/.codex` serves sandboxed tools that manage Codex state, such as `gh skill update --agent codex`; codex itself runs excluded. Sandboxed writes to the chezmoi-managed `~/.codex/config.toml` become possible as a side effect, so treat unexplained drift there as suspect.
- `~/.claude`, `~/.pi`, `~/.config`, `~/.local/bin`, and `~/.local/state/rexume` were added by user decision: agent session stores (such as renaming a Pi session directory after a project moves), tool configuration and entrypoints, and the Rexume state that `rexume task` writes from a sandboxed shell. Claude's built-in write denies inside `~/.claude` still apply, and credential files such as `~/.pi/agent/auth.json` are protected by the guard, not the sandbox.
- `~/Code/worktrees` is where the shared execution-host instructions put worktrees that outlive their task; move the entry if those instructions name another directory.
- `~/.gnupg/trustdb.gpg` is the only writable path under `~/.gnupg`. gpg opens the trust database read-write and falls back to read-only only on `EACCES` or `EROFS`; Seatbelt returns `EPERM`, and with keyboxd the resulting fatal error deadlocks gpg on exit, so sandboxed signature verification hung. The cost is that any sandboxed command can rewrite ownertrust, which decides what `%G?` reports. After a key import or ownertrust change, the first sandboxed verification still hangs on the trust-check lock until any trust-using gpg call runs outside the sandbox. Do not cover that window with `no-auto-check-trustdb`: it is global, so the database would never refresh and the user's own key would show `[unknown]`. Remove the entry once GnuPG opens a write-denied trust database read-only.
- The rendered `getconf DARWIN_USER_TEMP_DIR` entry exists because macOS `mktemp` without `-p` or an explicit template ignores the sandbox's `TMPDIR`, and Claude's built-in allowlist dropped that directory ([sandbox-runtime#182](https://github.com/anthropics/sandbox-runtime/pull/182)). Without it those calls fail in scripts and third-party tools, and agents retried them unsandboxed, so do not trade it for rewriting callers. Keep the exact `T/` path rather than a `/var/folders` glob, which would reopen the `C/` and `0/` siblings. Remove it only once Claude grants that directory again, tested with an isolated `CLAUDE_CONFIG_DIR`, because merged user settings make an in-place removal test pass falsely.
- `~/.oracle/sessions` alone is writable, so sandboxed commands cannot rewrite `~/.oracle/config.json`; Oracle fails at startup with `EPERM` without it.
- `/private/tmp/diff.*` serves macOS `/usr/bin/diff`, which copies pipe or process-substitution input to a hardcoded `/tmp` path. Remove it once `diff` honors `TMPDIR`.

### Reads, network, and sockets

- `denyRead` covers `~/.ssh` and `allowRead` reopens the files the guard allows, as patterns (`*.pub`, `config.*`) rather than key names. A `Read(~/.ssh/...)` deny would also feed the sandbox and block public keys there. Test pattern support with an isolated `--settings` file, because merged user settings mask a removal.
- Add an allowed domain only after observed sandbox traffic; excluded commands never consult the list. `*.host` matches subdomains but not `host`, so list both when both are needed. After the private hosts rendered from chezmoi data, order entries by registrable domain with a bare host before its wildcard. Keep `network.strictAllowlist` unset: under `auto` mode, a host outside the list is reachable only through a per-command allowed-domains list the classifier reviews, and strict mode would refuse those too. Promote a host into the list once sessions keep naming it.
- `allowUnixSockets` entries and the cost each one carries:
  - The gpg-agent, gpg-agent SSH, and keyboxd sockets serve `gpg`, `ssh`, and Git whenever those calls run sandboxed, as with `git -C`, Git inside a mixed command, or Git under `gh`, `glab`, or a hook. Without the keyboxd entry, `gpg` reports `no keyboxd running in this session` while the daemon runs.
  - The OrbStack socket lets sandboxed scripts use Docker; containers run outside the sandbox.
  - The Rex server socket was chosen by the user over a `rex` exclusion, accepting that any sandboxed process reaching it can run commands unsandboxed; the `orc` skill carries the rule against using that path. A sandboxed `rex` cannot start a missing server (`Bootstrap failed: 5`), so the server runs under launchd.
  - The ra broker socket was chosen over a `ra` exclusion, which would miss the piped, redirected, or `cd`-prefixed calls agents usually write. The user accepted that any sandboxed process reaching it can submit RA runs through the user's login without Chrome's per-connection prompt; the broker opens only RA pages.
  - The Maskey socket reaches Maskey's Keychain service, which performs grants and revokes, every operation when direct Keychain access is unavailable, and, because `mk` cannot write its activity directory in this sandbox, the recording of every operation `mk activity` shows. Without the entry, operations still reach the Keychain directly but warn and go unrecorded. Do not give the sandbox that directory instead, since a writer could rewrite the record. The service answers only Maskey's signed executable and changes access only after owner approval, so the entry grants no more than running `mk`.
  - `/private/tmp/claude-<uid>` is the sandbox's own `TMPDIR`, where sandboxed Cargo builds through mbx bind their cache socket; without it each build warns and falls back to FIFOs. Follow it if Claude moves the sandbox `TMPDIR`.
- `allowLocalBinding=true` also emits outbound access to `localhost:*`, so sandboxed clients of a local server depend on it too; do not narrow it to the server side.
- `com.apple.trustd.agent` in `allowMachLookup` lets Go-based CLIs verify certificates; the only alternative is `enableWeakerNetworkIsolation`, which the schema labels a security reduction. Mach lookup entries cannot fix Chromium's `bootstrap_check_in` denial, which needs `mach-register` ([report](https://github.com/anthropics/claude-code/issues/82660), [capability request](https://github.com/anthropics/sandbox-runtime/issues/210)); the shared execution-host instructions own that check.
- `NODE_USE_ENV_PROXY=1` makes Node's `fetch` honor the sandbox proxy; without it sandboxed Node CLIs such as `ctx7` fail with `fetch failed` even for allowed hosts. It is inert when `HTTPS_PROXY` is unset. Remove it only after a sandboxed Node CLI using `fetch` succeeds without it in a cleanly restarted session.

## Models, context, and statusline

- The alias variables pin exact model IDs because on Vertex, which gateway mode uses, the built-in table maps `sonnet` and `haiku` to 4.5 models, and because the gateway's clearance rules match exact IDs. The pin also stops an upgrade from moving an alias, so re-check it when a model generation ships. Omit `[1m]`: the pinned models are natively 1M. Delegation call sites accept only bare aliases, so model IDs live only in these variables.
- `autoCompactWindow` is 350K for every model, trading the weekly limit against compactions: in a cost replay of this machine's Opus 5.5 history, 1M cost 1.2 times 400K, and each 50K step below 400K saved about 3% while compactions grew faster. Raise it if compaction visibly hurts long tasks or the weekly limit stops binding. A `/autocompact` value saved under `modelSettings` outranks it, even as `auto`; delete that entry to return a model to 350K.
- Measure the context window from `modelUsage[].contextWindow` in `claude -p --output-format json` or the statusline's `context_window.context_window_size`; neither `autoCompactWindow` nor the picker's 1M label measures it. `dot_claude/scripts/executable_statusline.sh` owns its compact-window parser and denominator; update and test both when changing `autoCompactWindow`.
- `promptCacheTtl: "1h"` is for gateway mode, which otherwise caches for 5 minutes; subscriptions already default to 1h. Keep `ENABLE_PROMPT_CACHING_1H` unset: it would also move subagents, workflows, and helper requests to 1h, whose short idle gaps rarely repay the write premium.

## Integrations

- Keep `CLAUDE_CODE_ENABLE_CFC=0` explicit: unset, the client falls back to `claudeInChromeDefaultEnabled` in `~/.claude.json`. It does not govern the `chrome-devtools` MCP tools.
- `CLAUDE_CODE_DISABLE_CRON=1` removes `/loop` and the Cron tools, but `ScheduleWakeup` still registers, hence its deny. Remove the deny only after a fresh and a resumed session with the flag both expose no way to create, keep, or run a scheduled wakeup.
- `disableBundledSkills=true` keeps the repository-managed skill registry authoritative. Keep `disableWorkflows` unset because `ultracode` depends on dynamic workflows.
- `preallow@entwining-mods` is the user's own plugin; its README says what it reads. Keep `pluginConfigs` undeclared so its per-machine `model` and `effort` survive applies.
- Keep `leftArrowOpensAgents: false` to prevent accidental backgrounding of Rexume workers. Rexume binds a task to one conversation, and backgrounding with `←` continues the conversation under a new session ID, so the task stops collecting its turns while `task send` still targets the original one. The setting disables only the foreground `←` shortcut; `claude agents` and `/bg` remain available. Re-enable the shortcut once backgrounding a registered worker preserves turn collection and request delivery.
- `crossSessionInbound: "accept"` is a user decision. Unset, Claude Code holds a peer message for approval when the sender's permission-mode class differs from the receiver's, and holds one that asserts no class, as Rexume's do, while the receiver bypasses permission prompts; Rexume's plugin cannot cover the window after the user stops a turn, so a bypass worker would wait for the user there. The hold guards little on this machine, because any session that can run Bash already reaches unsandboxed execution through the Rex socket; revisit it if that socket leaves `allowUnixSockets`.
- Rex's `SessionStart` command and Rexume's `SessionStart`, `UserPromptSubmit`, `Stop`, and `StopFailure` commands stay verbatim so [their installers recognize the source-owned registrations](../../.github/CONCEPTS.md#rex-integration).
- `worktree.baseRef` stays unset, so new worktrees branch from `origin/<default-branch>` rather than carrying local HEAD state.
