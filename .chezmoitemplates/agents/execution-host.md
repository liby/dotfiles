## Execution Host

Create scratch files and directories in runtime-provided temporary space under unique names, such as those `mktemp` returns, and keep each path where later calls can see it: a shell variable ends with the command that set it, so print the path in that command's output or remove the file before the command ends. Remove exactly those paths once the task no longer needs them. Other sessions and agents share that space and the machine's temporary roots such as `/tmp`, so never delete in shared temporary space by a wildcard or by any path other than one you created and kept; a name you find later by listing or matching a prefix can belong to another session, so leave a scratch path you did not keep where it is.

Create new Git worktrees outside every project checkout, since Git ignore rules do not keep recursive build, lint, and test tools from scanning nested sources. Put a worktree that must survive the task in `~/Code/worktrees`. Any other worktree is scratch, and the directory `mktemp -d` returns is the worktree itself, as in `wt=$(mktemp -d "$TMPDIR/<repo>-wt.XXXXXX") && git worktree add "$wt" <ref>`: Git names the worktree's metadata after that directory's name, and a sandbox can keep denying a name registered earlier in the session.

When starting Codex in a directory you created for the task, pass `-c 'projects={"<path>"={trust_level="trusted"}}'` with `<path>` taken from `pwd -P` in the launch directory. This keeps trust out of the user's config, even with `--ephemeral` or `--sandbox read-only`. When a read-only Codex launch is requested, report that this Mac's managed permission profile retains write access.

`claude` on PATH is a launcher that runs Claude Code on the subscription or the gateway: `--subscription` or `--gateway` as its first argument picks the route for that launch, and without either it takes the saved mode, which can differ from the route the task calls for.

Approval to escalate does not prove that a command escaped an inherited OS sandbox. Before a task creates its own OS sandbox, run a no-op under the task's sandbox profile from the intended execution context. Before launching a GUI application or headless browser, directly or through a test runner, script, or Git hook that starts one, and when another command reports an OS sandbox restriction, check the required OS capability in the actual execution context without launching the application as a probe. A macOS Seatbelt command sandbox on this machine denies the Mach service registration that a Chromium-based browser's normal multiprocess launch needs, so the browser aborts with `bootstrap_check_in ... Permission denied (1100)`, a failure of the context rather than of the code under test. If that context lacks the capability, submit the exact operation for review through a terminal context that provides it, verify that context, and then run it; where approved escalation stays inside the sandbox, a Rex terminal is that context.

For headless browser jobs you launch, use a dedicated automation binary such as Chrome for Testing or chrome-headless-shell. Set a finite execution deadline and ensure the job's browser processes terminate when the job ends or times out. Never launch these jobs with `/Applications/Google Chrome.app`: a hung headless instance can hold the Chrome app identity and prevent normal GUI launches. When connected to the user's existing browser, release automation control when finished instead of terminating the browser or closing the user's tabs.

Scope filesystem searches to the checkout or an explicit target. A recursive scan that walks from `$HOME`, `/`, or `~/Library` reads other apps' data containers, and macOS records each one as a Files & Folders App Data entry under this process's responsible app, so keep `~/Library` (including its `Containers`, `Group Containers`, `Mobile Documents`, and `CloudStorage` subtrees) out of traversals and name the one path a task needs instead.

When GnuPG reports a signing or decryption failure, read `~/.agents/gnupg.md` before retrying or choosing a recovery action.
