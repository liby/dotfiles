## Execution Host

Create scratch files and directories in runtime-provided temporary space under unique names, such as those `mktemp` returns, and keep each path where later calls can see it: a shell variable ends with the command that set it, so print the path in that command's output or remove the file before the command ends. Remove exactly those paths once the task no longer needs them. Other sessions and agents share that space and the machine's temporary roots such as `/tmp`, so never delete in shared temporary space by a wildcard or by any path other than one you created and kept; a name you find later by listing or matching a prefix can belong to another session, so leave a scratch path you did not keep where it is.

Create Git worktrees outside every project checkout because recursive build, lint, and test tools can scan Git-ignored sources. Put worktrees that must outlive the task in `~/Code/worktrees`. For all other worktrees, use the `mktemp -d` directory itself as the scratch worktree, as in `wt=$(mktemp -d "$TMPDIR/<repo>-wt.XXXXXX") && git worktree add "$wt" <ref>`. Git names its metadata after that directory, and the sandbox can keep denying a name registered earlier in the session.

For Codex in a directory you created for the task, pass `-c 'projects={"<path>"={trust_level="trusted"}}'` with `<path>` from `pwd -P` there. This keeps trust out of the user's config even with `--ephemeral` or `--sandbox read-only`. For a requested read-only Codex launch, report that this Mac's managed permission profile retains write access.

The `claude` launcher on PATH selects the Claude Code subscription or gateway for one launch with `--subscription` or `--gateway` as its first argument. Otherwise it uses the saved mode, which can differ from the task's route.

Approved escalation can retain an inherited OS sandbox. Before creating a task's own OS sandbox, run a no-op under its profile in the intended execution context. Before launching a GUI application or headless browser directly or through a test runner, script, or Git hook that starts one, or when another command reports an OS sandbox restriction, check the required OS capability in the actual context without launching the application as a probe. This Mac's Seatbelt command sandbox denies the Mach service registration Chromium needs for normal multiprocess launch. Attribute the resulting `bootstrap_check_in ... Permission denied (1100)` browser abort to the execution context and rule out the code under test as its cause. If the capability is missing, submit the exact operation for review through a capable terminal context, verify the context, then run it. Use a Rex terminal for this review and execution if approved escalation stays inside the sandbox.

For headless browser jobs you launch, use a dedicated automation binary such as Chrome for Testing or chrome-headless-shell, whose app identity is separate from `/Applications/Google Chrome.app`: a hung headless instance of that app holds its identity and keeps normal GUI launches from opening a window. Set a finite execution deadline and ensure the job's browser processes terminate when the job ends or times out. When connected to the user's existing browser, release automation control when finished instead of terminating the browser or closing the user's tabs.

When GnuPG reports a signing or decryption failure, read `~/.agents/gnupg.md` before retrying or choosing a recovery action.
