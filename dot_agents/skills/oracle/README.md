# Oracle local policy

`SKILL.md` records its reviewed upstream source. An upstream skill update may
replace both files, so recover them from git and reapply only decisions that
still have current evidence.

Revalidate these local deltas after an update:

- Explicit web consultations use the reviewed global CLI, attach-running, a
  dedicated tab, the latest ChatGPT model reviewed for that CLI release, and
  explicit fail-closed `pro` effort. No floating Pro alias, profile copy,
  inherited tab, model substitution, or API fallback.
- The request authorizes its browser-subscription route; API billing needs
  separate consent, and private input remains excluded.
- A supplied Project is a completion requirement. Fresh roots, browser
  follow-ups, API follow-ups, and manual submissions have distinct evidence.
- Automated runs verify model version and Pro effort separately, then wait for
  terminal output. Manual runs preserve original inputs, render only text,
  attach non-text inputs in byte-preserving form, and require visible completed
  output plus a saved conversation URL.
- Keep provenance aligned with the version in the global-tools manifest, and
  recheck the latest model plus current CLI/source behavior. Update the pinned
  model contract on every relevant release; never retain a patch solely because
  an older version needed it or infer removal from a hidden help entry.
